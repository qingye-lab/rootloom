## Failure analysis and corrections

The three failures in the prior retained result were scoring false negatives:

- Public API did load both Governed References successfully, but a later relative
  command was not associated with the previously observed Skill directory;
- Review-only described the suppressed failure and test-ratified false-connected state
  using equivalent wording;
- Data Migration described idempotency as repeat-safe, byte-for-byte unchanged, or an
  exact no-op.

Mechanical scoring v4 resolves successful later-relative reads, quoted plugin paths
containing spaces, and those bounded equivalent completion signals. Failed commands
still do not count as activated context.

The new formal matrix then found a separate real failure: Project Guidance repetition 2
left `service/.pytest_cache/**` while claiming that only `service/AGENTS.md` changed.
The Skill now requires a final starting-state and authorized-path comparison, prefers
no-cache verification, and permits removal only of artifacts created by the current
task. All three replacement Seed runs changed exactly `service/AGENTS.md`; all three
Validate runs changed nothing.
