# Rootloom 4.4：按任务需要组织日常流程

- 状态：已接受；正式发布另行审批
- 日期：2026-09-05
- 责任方：Rootloom 维护者
- 范围：Core 默认指导、大文件路由、发布验收
- 替代：下文链接的旧流程默认值
- 被替代：无

## 背景

Astra [模型指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)
建议审计指令冲突并按任务校准自主执行与验证。Rootloom 原有全局和 Skill 流程重复，固定
输出字段，并在有界读取已足够时要求大文件 Worker；措辞锁定也使正常精炼无法通过校验。

## 证据

全局规范源为 `plugins/rootloom/assets/system/AGENTS.md`，四个 Skill 在
`plugins/rootloom/skills/`。项目块分类由 `project-guidance/scripts/seed_project_guidance.py`
实现，打包一致性与 Setup 恢复由 `scripts/validate_repo.py` 和既有测试验证。
`evals/core-reset/` 中的历史行为结果保留原始版本身份。

## 决策

保留持久事实、真实权限边界和完成证据。全局指导负责范围与授权，四个现有 Core Skill
按条件解释流程，并为 Skills-only 安装保留最小自包含保障。用户意图授权工作，只读诊断
不授权修复，独立审批和阶段验收保留。不新增或改变公共 Skill、授权模式、安装 CLI、
缓存 Schema 和冻结 Evidence 格式。

自然语言明确要求优化指定指导文件即可触发。仓库泛化文字与普通编码任务不授权持久化；
现有精确单文件 Refine Marker 继续有效。编辑前解析真实路径；生成项目事实使用 Probe
和项目 Marker，措辞优化采用定点检查。全局块、备份、漂移拒绝与用户后缀保护仍归 Setup。

大文件缓存与无历史 Worker 是按收益选择的性能工具。默认按任务需要有界读取；没有
Worker 不阻塞普通工作，用户明确隔离、文件权限、上传与保留要求仍优先。不因文件已被
读取就要求另开任务。

仓库检查保留容量上限、文件与 Marker 结构、真实路径边界和打包一致性；删除最低字数、
规则条数与纯流程措辞匹配。可执行保障由行为测试证明，不增加替代关键词清单。

## 发布验收

完整历史评估工具及绑定版本的结果继续供主动研究使用；固定 135 个 Cell 的矩阵及效率
阈值不再强制每次发布运行。这替代了 [4.1 效率决策](2026-07-29-rootloom-4.1-efficiency-loop.md)
中的默认发布门禁，以及[大文件决策](2026-08-13-artifact-context-lane.md)中的强制路由。

按变更行为选择确定性检查，保留既有 CI。本次工作流调整使用六个场景，每个当前版和
候选版各一次，同 Astra 模型、推理强度和隔离 Fixture 下串行运行：只读诊断；保留脏
工作树的授权修复；自然语言指导优化与外部软链接；无 Worker 大文件读取；精确模拟
授权；如实报告验证失败。

候选须完成已授权结果，不得越权、丢失用户修改或虚报验证。记录无必要询问、提前停止、
检查范围、耗时与可获得用量。耗时只作观察，小样本不能证明普遍提速。出现问题只修复并
复测受影响场景，不自动扩矩阵。原始模型事件和一次性执行记录不进仓库，PR 保存发布
证据；不改写历史评分为新候选背书。

## 影响

日常工作减少流程步骤，但语义质量仍需审查；删除措辞断言不能删除运行时保障。发布保留
准备完成后的单次最终审批；本机通过正式来源与既有 Setup 计划、备份和升级流程更新，
保持已选能力及无关设置。

## 考虑过的替代方案

- 保留强制 Worker 与历史全矩阵：有界读取与小型指导变更无需这些成本，改为明确选用。
- 删除全部指导：会丢失独有项目事实和权限边界。
- 强制更短提示词：篇幅不能证明任务行为正确。

## 验证

使用前述针对性确定性检查和六组配对场景；可审阅 PR 记录实际结果与安装影响。
相应本机更新仍须执行 Setup 计划、状态和备份检查。

## 重新评估条件

当可复现任务失败、权限歧义、改动丢失、虚假验证或重复读取成本证明某个默认值不足时，
重新评估对应规则。
